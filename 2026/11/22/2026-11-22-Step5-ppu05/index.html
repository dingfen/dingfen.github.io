Step-5 的 Q/K 归一化与 RoPE：一次调度完成，顺手写入 KV cache

更新于：2026-11-22T20:10:25+08:00

Step-5 的 Q、K 做完归一化和 RoPE 后，怎样少启动两次 kernel？

在一段 Step-5 decode trace 里，每层注意力开头都有两次很短的调用。第一项处理 Q，平均 2.45 µs。第二项处理 K/V，平均 2.53 µs。到了稀疏注意力层（DSA），紧接着还有一次 2.45 µs 的 KV cache 写入。要把这三步合起来，需要先看清两件事：哪些行可以同时算，以及 K/V 最终该写到哪里。

改法是让同一个网格里的不同线程块分别处理 Q 和 K/V。负责 K/V 的线程块已经拿到结果，只要后端能提前给出缓存槽位，就能把值直接写过去。

Q 和 K 可以一起发出去

举一个实际形状。16 个 token，每个有 4 个 Q head，每个 head 宽 192。原先第一批线程块处理 16 × 4 个 Q 行，第二批处理 16 个 K/V 行。Q 和 K 各用自己的归一化权重，对各自的行做 RMSNorm 和旋转位置编码（RoPE）。同一 token 的 Q 无需等 K，K 也无需等 Q。

把调度网格改成 16 × 5 即可。每个 token 的前四个位置各处理一个 Q head，第五个位置处理 K，并读出 V。Q、K 仍从原来的地址读取，各用各的权重；V 直接取原值。这样原本单独发出的 16 个 K/V 线程块就可以和 Q 一起调度。固定 16 token、4 个 Q head 做微基准，两次调用合计 4.86 µs，合并后 2.54 µs。

写 cache 前要拿到正确的槽位

滑窗注意力层（SWA）当时已经能在算完 K/V 时直接写 cache。DSA 仍走另一条路：先写出 K/V，再让 set_kv_buffer 取回这两行，写入保存完整历史的缓存池。K 是刚算出的结果，V 也已经读入，第二次调用可以省掉。难点是千万别照搬滑窗层的目标地址。

SWA 用滑窗池的槽位，DSA 用 full 池的槽位。在适用配置下，这两个写入动作都是“把一行 192 个 BF16 值写进指定槽”。后端先按层找到缓存池，再把 K 缓冲、V 缓冲和槽位交给同一个计算 kernel。只有这组目标可用，调用方才跳过原来的写入。缓存需要量化缩放、槽位还需翻译，或者 K/V 的行宽、类型、布局不匹配时，都继续走原来的缓存接口。验证时既要比 K/V 的值，也要比它们最终写到的物理行，尤其是无效槽位不能被覆盖。归一化与写回实现 · 对照测试

共同的输出只计一次

同一组报告中，旧 Q 与 K/V 平均合计 4.98 µs，DSA 层还要加上 2.45 µs 的独立写入。合并后，报告将新 kernel 汇总为平均 3.26 µs，这个数已经包含在适用层写 cache 的成本。

按每轮调用计数，95 次 Q 和 95 次 K/V 合成 95 次调用，又省掉了 23 次 DSA cache 写入，总共少启动 118 次。用报告里的各项设备时长核算，合计每轮约省 0.22 ms。这种算法只算一次新 kernel，也避免把同一次缓存写入产生的收益重复记到两处。
